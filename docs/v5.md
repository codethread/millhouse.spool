# Millhouse v5

v5 is a single breaking release of the independently consumable Millhouse spools.
There are no old-coordinate dependencies, namespace aliases, or compatibility
modules. Package roots and the declared production dependency graph are unchanged.

## Names

| Previous name | v5 name |
| --- | --- |
| `millhouse.spools/<package>` | `millhouse/<package>` |
| `ct.spools/harnesses` | `millhouse/harnesses` |
| `codethread/devflow` | `millhouse/devflow` |
| `codethread/devflow-kanban-adapter` | `millhouse/devflow-kanban-adapter` |
| `codethread/config` | `millhouse/config` |
| `millhouse.spools.*` | `millhouse.*` |
| `ct.spools.harnesses*` | `millhouse.harnesses*` |
| `ct.spools.devflow*` | `millhouse.devflow*` |
| `ct.spools.codethread.config` | `millhouse.config` |
| `ct.spools.codethread.<component>` | `millhouse.config.<component>` |
| `@codethread/harnesses` | `@millhouse/harnesses` |

Source, resource, test, and exported clj-kondo paths follow the new names. The
GitHub owner remains `codethread`; the repository URL has not changed.

Bootstrap module IDs also change: `:millhouse/spools-*` becomes `:millhouse/*`,
`:millstrand/spools-harnesses` becomes `:millhouse/harnesses`,
`:millstrand/spools-agent-executor` becomes `:millhouse/agent-executor`, and
`:codethread/config*` becomes `:millhouse/config*`. Update explicit `:after` edges
with the registrations. Millstrand core's own module IDs are unchanged.

Auto-run's scheduler key is now `millhouse/auto-run`; its explain schema is
`millhouse.auto-run.explain/v1`. Ordinary domain attributes such as `kanban/*`,
`workflow/*`, and `harness/*` retain their names.

## Consumer cutover

1. Resolve tag `v5` to its full commit SHA. Select all required roots using
   `scripts/consumer-deps.sh SHA millhouse/config ...` from that checkout. Replace
   old dependencies with the generated direct closure, all at that same SHA.
   Do not mix pre-v5 and v5 spool roots. Millhouse itself uses checkout-local roots.
2. Rename requires, qualified symbols, source/resource paths, module IDs and
   ordering edges together. Keep activation explicit and register the agent
   executor last. Config's entry points are now
   `millhouse.config.bootstrap/register!` and `register-executor!`.
3. Refresh generated clj-kondo imports. If consuming native Harnesses plugins,
   change the package dependency/imports to `@millhouse/harnesses` and the
   `spools/harnesses` root at the same commit, then regenerate the package lock.
4. Verify classpath provenance and actual consumer activation in disposable
   worlds before changing a live generation. Update ignored local dependency
   overlays too when they override the checked-in selection. Run
   `scripts/verify-editor-diagnostics.sh SHA` against the selected published
   revision to verify owner-exported clj-kondo configuration in clojure-lsp.
5. Drain or explicitly reconcile active work using old qualified callbacks before
   an authorized Weaver restart. Persisted workflow definitions and callbacks are
   not rewritten by this release. Preserve their history; do not manufacture
   completion or replay external side effects. Never stop Mill to apply a pin bump.

The repository-owned automatic-delivery namespaces live under
`millhouse.workspace.*` to avoid colliding with the published `millhouse.auto-run`
spool. Dated reports and immutable source links remain historical evidence.
