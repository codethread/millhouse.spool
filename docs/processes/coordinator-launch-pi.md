# Pi coordinator launch policy

Apply this file only to an explicitly selected Pi coordinator launch, alongside the generic runbook and bounded assignment. Shared sub-coordinator aliases now resolve through Codex; this policy does not switch them back to Pi. It is the Pi default timing policy, not an automatic CLI setting or evidence about old sessions. An explicit harness/agent override must record its reason, inner wait, client deadline and outer-tool behavior in the launch and coordinator task note.

Keep the headed Pi process in the assigned repository's canonical root. Start its initial interactive prompt with exactly `/goal ` followed by the bounded assignment. Verify the real Pi goal ID and active state in public goal/session state, not a Strand attribute or a visible TUI alone. Retain the harness's goal guards; do not alter them as a launch workaround. Record native session, tracked request/run, identity, canonical CWD and discoverable terminal.

Default owned-work observation is an event-aware **180-second** Strand await. Use `strand --timeout 210s await ... --timeout-secs 180`, or `strand --timeout 210s workflow await RUN --timeout-secs 180`. Prefer the blocking shell tool with a timeout of at least 240 seconds. A positive event returns early and must be handled immediately; do not sleep unconditionally for three minutes. If a tool yields asynchronously, wait on that same command with an adequate deadline rather than starting another await or seconds-long polling. Overrides must be explicit, not inferred from historical short-wait examples.

After a result/timeout, read compact owned work and relevant current run and coordinator/child task notes, then act or reissue. Never substitute `goal_wait` for owned Strand worker/review/workflow progress. That tool is only for an active Pi goal parked for an arranged external wake/deadline, not a Strand subscription. Terminal, settlement and acceptance differ; healthy validation or normal timeout is not failure. Complete the goal only after required Kanban outcomes are accepted or acknowledged handoffs. Never stop or restart Mill. Delegate only through tracked Strand, never Pi/native or built-in helpers.
